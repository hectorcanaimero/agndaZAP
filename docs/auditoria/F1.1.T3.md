# F1.1.T3 — Reconciliar SPEC.md (y ARCHITECTURE.md) con los sprints post-08-18

**Objetivo:** `SPEC.md` quedó desactualizado tras los sprints de observabilidad, health,
admin-audit e HMAC (ADRs 0014–0017) y las features de leads/feedback/follow-ups/invitations.
Este reporte lista los hallazgos y produce el **diff concreto** listo para una task de edición.

**Alcance:** `docs/SPEC.md` (principal) y `docs/ARCHITECTURE.md` (secundario). No se editan
los artefactos en esta task — solo se produce el diff.

**Veredicto global:** sin bugs de código; el drift es **de documentación** pero con impacto de
contrato. Ningún hallazgo es P0 (el código está correcto y hardenizado), pero hay 7 P1 que
deben cerrarse antes del GO de las 40 clínicas porque SPEC.md es el contrato que consume el
equipo para integrar y operar.

#### 1.2 INSERTAR regla de negocio "Impersonation + AdminAudit" en §2

Insertar al final de §2 (después de "### Bot", línea 74):

```markdown
### Impersonation y trail de auditoría (SUPERADMIN)
- Impersonation genera un JWT temporal de 30 min con payload
  `{ sub, role: 'CLINIC_ADMIN', clinicId, impersonatedBy: sub }`; el SUPERADMIN nunca lleva
  `clinicId` propio.
- Toda mutation (POST/PATCH/DELETE) ejecutada bajo un JWT con `impersonatedBy` queda en
  `AdminAudit` con `action = IMPERSONATED_WRITE`, `targetType` inferido del path, `targetId`
  de `req.params.id` y `metadata = { method, path, clinicId }`. Las mutations de CLINIC_ADMIN
  normales NO generan filas (evita ruido). El body NUNCA se persiste en `AdminAudit` (puede
  tener PII).
- `AuthService.login()` rechaza con 403 si `clinic.status != ACTIVE` (SUSPENDED/ARCHIVED);
  no aplica al SUPERADMIN (no tiene clínica).
```

#### 1.4 REEMPLAZAR subsección "Webhook" (líneas 36-37)

Reemplazar por:

```markdown
### Webhook
- `POST /webhooks/waha` → eventos de WAHA (público). Autenticación (ver ADR 0017), en orden:
  1. HMAC-SHA256: header `x-webhook-hmac` sobre el body raw (`WEBHOOK_HMAC_SECRET`, timing-safe).
  2. Fallback shared token: header `x-webhook-token` (`WEBHOOK_TOKEN`).
  3. Solo dev: `ALLOW_WEBHOOK_WITHOUT_TOKEN=true` Y `NODE_ENV!=production`.
  Si `WEBHOOK_HMAC_SECRET` está seteado, el token se ignora (anti-downgrade). Cualquier otro
  caso → 403 (fail-closed). El body se firma sobre bytes raw (`req.rawBody`), no sobre
  `JSON.stringify`.
```
