# Reporte Auditoría: F1.6.T2 - Infra, deploy y parity de env

- [P0] Faltan los `ARG` y `ENV` de Sentry en `apps/web/Dockerfile`
  - Gap: Los compose files (`docker-compose.prod.yml` y `docker-compose.coolify.yml`) definen múltiples variables en `args:` para el build del frontend (`NEXT_PUBLIC_SENTRY_*`, `SENTRY_ORG`, `SENTRY_AUTH_TOKEN`, etc.). Sin embargo, el `Dockerfile` de Next.js solo declara `ARG NEXT_PUBLIC_API_URL` e ignora el resto.
  - Evidencia: `apps/web/Dockerfile` línea 30. No hay declaraciones `ARG` ni `ENV` para Sentry antes del `RUN pnpm build`.
  - Impacto lanzamiento: Crítico. Sentry queda deshabilitado en el cliente/browser porque Next.js no puede embeber `NEXT_PUBLIC_SENTRY_DSN` en el bundle. Tampoco se suben los source maps en build-time porque el CLI de Sentry no lee el token.
  - Recomendación: Task de finalización para agregar los `ARG` y `ENV` correspondientes en el stage `build` de `apps/web/Dockerfile`.

- [P1] Referencia a `docs/deploy-coolify.md` inexistente
  - Gap: `docker-compose.coolify.yml` instruye al usuario a leer `docs/deploy-coolify.md` para ver el mapeo de dominios de Coolify, pero el archivo no existe.
  - Evidencia: `docker-compose.coolify.yml:19` (comentario). No existe `docs/deploy-coolify.md` en el repositorio.
  - Impacto lanzamiento: Falta de documentación operativa (runbook) si el piloto usa Coolify, especialmente crítico para documentar cómo emular el IP Allowlist de Traefik para el dashboard de WAHA (que sí está documentado para Caddy en `docs/deploy.md`).
  - Recomendación: Crear `docs/deploy-coolify.md` con las instrucciones necesarias, o remover el compose si Coolify no será opción soportada para este lanzamiento.

- [P2] Inconsistencia en `CORS_ORIGINS` del runbook
  - Gap: `docs/runbook-lanzamiento.md` pide configurar `CORS_ORIGINS=https://<dominio-panel>,https://<dominio-backend>`. El dominio del backend no es un origen desde el cual se hagan peticiones browser (XHR/fetch) cruzadas a sí mismo o a otro servicio.
  - Evidencia: `docs/runbook-lanzamiento.md` línea 58.
  - Impacto lanzamiento: Nulo en términos de riesgo, pero genera confusión y una configuración CORS innecesariamente holgada.
  - Recomendación: Corregir el runbook para que solo pida el `<dominio-panel>` como origen.

- [Sin hallazgos P0/P1] Paridad de `.env.example` vs `process.env`
  - Todas las variables definidas en el ejemplo están correctamente consumidas en el backend/frontend, y se agregaron flags ocultas en modo correcto (`SEED_ALLOW_PROD` y `CONFIRM_PROD_REINDEX` comprobadas en scripts de prisma).
  
- [Sin hallazgos P0/P1] Healthchecks y start_period
  - Los healthchecks en `docker-compose.prod.yml` y `.coolify.yml` están alineados a `docs/runbook-lanzamiento.md`. El backend verifica liveness pura (`/api/health/live`) con `start_period: 60s`, y WAHA/web con `30s` y verificando credenciales correctamente.
